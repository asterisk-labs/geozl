Four calls cover most use. profile measures candidate recipes on a tile, graph builds one, compress runs tiles through it and decompress reads a frame back. The notebook runs them on a DEM tile.

The four calls

import numpy as np
import geozl

y, x = np.mgrid[0:256, 0:256]
tile = (1000 + 3 * x + 2 * y).astype(np.int16)

rows = geozl.profile(tile)                  # candidates, best ratio first
g = geozl.graph(tile, rows[0]["graph"])     # build the chosen recipe once
frame = geozl.compress(tile, graph=g)       # bytes
back = geozl.decompress(frame).view(tile.dtype).reshape(tile.shape)
assert np.array_equal(back, tile)

A frame stores no dtype or shape. Keep them beside it, as Rumi does.

Frames can also decode straight into device memory on a GPU. That call is in C, and GPU decoding walks through it. The language bindings decode on the CPU only.

Languages

PythonThe full API, with the OpenZL nodes in geozl.lossless and geozl.lossy. pip install geozl
CThe library every binding calls, with graphs, nodes, coefficients and GPU decode. Built from the repository with make lib.
RThe four calls and geozl_coeffs, on double, integer and raw vectors. From the asterisk-labs r-universe.
JuliaThe four calls and coeffs, on native Julia arrays. Pkg.add("GeoZL") from the Asterisk registry.
JavaScriptOne-shot compress and decompress on raw bytes, in WebAssembly. npm install @asterisk-labs/geozl
