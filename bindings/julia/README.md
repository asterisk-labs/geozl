# GeoZL.jl

Julia bindings to GeoZL. They have the same graph, compress, decompress and
profile calls as the Python and R packages and write the same frames.

```julia
using GeoZL

tile = [UInt16(2000 + 5 * (x - 1) + 8 * (y - 1)) for x in 1:1024, y in 1:1024]

GeoZL.profile(tile; reps = 1)

g = GeoZL.graph(tile, "planar>zigzag>pfor")
frame = GeoZL.compress(tile, g)
back = GeoZL.decompress(UInt16, frame, size(tile)...)
back == tile
```

## Install

```julia
using Pkg
Pkg.add(url = "https://github.com/asterisk-labs/geozl", subdir = "bindings/julia")
```

The package calls `libgeozl` directly. It looks for the library in this order:

1. `GEOZL_LIB_PATH`, for a library built anywhere.
2. `core/build/` of the repository the package sits in, which `make lib` fills.
3. The artifact a release publishes for Linux x86-64 and macOS arm64,
   downloaded on first use. The release's `Artifacts.toml` is kept in the
   depot under `geozl/`, so later sessions load offline.

## Rasters

- **Element types.** Julia's own `UInt8` to `UInt64`, `Int8` to `Int64`,
  `Float16`, `Float32` and `Float64`, with no conversion.
  `GeoZL.decompress(T, frame, dims...)` decodes straight into an `Array{T}`;
  without `T` it returns the raw bytes.
- **Layout.** The fastest-varying dimension is the row. An array shaped
  `(x, y)` or `(x, y, band)`, as Rasters.jl holds a raster, gives the same frame
  as Python does for `(y, x)` or `(band, y, x)`. Views and transposes are
  copied to dense samples first.
- **NoData.** `missing` values are stored as `nodata`, or as NaN in a float
  raster, and `GeoZL.decompress(T, frame, dims...; nodata = -9999)` turns the
  sentinel back into `missing`. NaN holes in a float raster are found without
  asking; a lossless frame keeps every NaN payload.
- **Bounded error.** `error = 0.5` bounds the absolute error, `error = "1%"`
  the relative error, and full `LINEAR`, `LOG` and `SQRT` recipes are accepted.
- **Coefficients.** `GeoZL.compress(x, g; coeffs = [[1, 2, 3]])` attaches
  integer vectors to a frame and `GeoZL.coeffs(frame)` reads them back.

A frame does not record its element type or shape. Keep them beside it, as
Rumi does. A `Graph` holds native state and is not thread-safe; build one per
task.

## Development

```sh
make julia    # build libgeozl, then Pkg.test() against it
```

The tests decode every golden frame and compare frames with Python's when
`GEOZL_PYTHON` names a Python with geozl, which `make julia` sets. A release
attaches the `libgeozl` tarballs and a matching `Artifacts.toml` generated by
`make-artifacts-toml.jl`.
